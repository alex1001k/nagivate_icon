Шаг 1 — Foreign Keys
DataHub сканирует схему и вытаскивает все foreign key автоматически.

Ничего писать не надо — просто подключить и запустить сканирование.
~35% связей
Шаг 2 — SQLGlot парсит SQL
Python-скрипт читает все SQL из query log, dbt, ETL, BI.

SQLGlot разбирает каждый запрос и извлекает: какие таблицы джойнились и по каким полям.

На выходе: список пар таблиц которые реально связаны в работе.
ещё ~35% связей
Шаг 3 — LLM на схему таблиц
Берёшь названия всех таблиц и колонок → скармливаешь в Claude или GPT-4.

Модель находит неочевидные совпадения: contract_number в кредитах и agreement_id в страховках — одно и то же.

Человек проверяет и подтверждает.
ещё ~20% связей
↓ всё собирается в одно место

Важно понять
Связи не надо писать вручную — они уже существуют в вашем query log, dbt и ETL. Нужно их просто извлечь. Query log PostgreSQL и Oracle хранит историю за месяцы — там десятки тысяч реальных запросов с JOIN-ами. Это и есть карта того как данные реально используются в банке каждый день.
